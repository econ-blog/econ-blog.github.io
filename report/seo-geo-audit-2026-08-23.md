# SEO/GEO 감사 — 2026-08-23

대상: https://econ-blog.github.io/ · 코퍼스 61건(뉴스 해설 33 · 용어 사전 28) · 사이트 연령 36일

## 0. 방법과 한계

- **크롤**: `hugo --environment production` 산출물을 `scripts/seo_geo_audit.py`로 훑었다.
  렌더된 HTML 115장 · 내부 링크 1,368개 · 외부 호스트 41개. 판정 원문은 JSON으로 나온다.
- **주간 감사(`/weekly-audit`)와 겹치지 않는다.** 저쪽은 `content/` 마크다운을 읽고 이쪽은
  **렌더 산출물**을 읽는다. 검색·답변엔진이 실제로 보는 것은 후자이며, 두 층이 어긋나는
  결함(테마가 삼키는 메타, 부분 렌더되는 JSON-LD, 페이지네이션 사본)은 마크다운 쪽에서
  원리적으로 보이지 않는다.
- **한계 1 — 라이브 사이트에 도달하지 못한다.** 샌드박스에서 `econ-blog.github.io`는
  연결되지 않는다(설계된 제약). 크롤 대상은 `origin/main`과 동일한 커밋을 로컬 빌드한
  것이며, 응답 헤더·실 HTTP 상태·CDN 동작은 측정하지 않았다.
- **한계 2 — 색인 실측은 직전 주간 감사값을 인용한다.** GSC 조회는 이 세션에서 하지
  않았다. `report/audit-2026-08-23.md` ③의 값: **60건 중 2건만 색인**(홈·`/dictionary/`),
  나머지는 대부분 "URL is unknown to Google". 네이버는 색인 17건.
- **한계 3 — 답변엔진에 직접 질의하지 못했다.** ChatGPT·Perplexity·Claude 답변 화면을
  호출할 수단이 없다. 그래서 GEO는 **결과**(인용되었는가)가 아니라 **입력**(답변엔진이
  읽어 갈 수 있는 형태인가)으로 측정했다 — llms.txt 커버리지, FAQ 추출 단위, 구조화된
  출처 표기. 이것은 대리 지표이며 인용률의 추정치가 아니다.
- **한계 4 — 쿼리 벤치마크의 검색엔진은 US 로케일이다.** 한국어 SERP의 실제 순위와
  다를 수 있다. 브랜드 쿼리에서도 사이트가 나오지 않는다는 사실 판정에만 쓴다.

## 4. 이번에 고친 것 — 1순위 A5

`static/llms.txt`(35줄)와 `static/llms-full.txt`(59줄)를 지우고 Hugo 출력 형식으로 대체했다.

- `hugo.toml` — `[outputFormats.llms]` · `[outputFormats.llmsfull]` 정의 후 `outputs.home`에 추가
- `layouts/home.llms.txt` — llmstxt.org 규약(H1 → 인용문 요약 → `## 섹션` → `- [제목](URL): 설명`)
- `layouts/home.llmsfull.txt` — 전 문서 마크다운 원문. 소제목·목록·링크 구조를 남겨야
  답변엔진이 문서 **안에서** 답이 있는 구간을 집어낼 수 있다. 루트 상대 링크는 절대 URL로 치환

| | 이전 | 이후 |
|---|---|---|
| llms.txt 크기 | 1.9 KB (손으로 작성) | 20.7 KB (생성) |
| llms.txt 수록 문서 | 15 / 61 (25%) | **61 / 61 (100%)** |
| llms-full.txt | 59줄 요약 8건, **본문 0자** | 281 KB, 61건 전문 + 출처 URL + FAQ |
| 새 글 발행 시 | 사람이 손으로 추가(실제로는 누락) | 자동 반영 |

이전 `llms.txt`는 `llms-full.txt`를 "Complete text version"이라고 가리켰지만 그 파일에는
본문이 한 글자도 없었다. 커버리지 결함인 동시에 **크롤러에게 한 거짓 약속**이었다.

`scripts/seo_geo_audit.py`(감사기)와 `scripts/test_seo_geo_audit.py`(단위 테스트 10건)를
함께 넣었다. 다음 감사는 같은 명령 한 줄로 재현된다.

4개 쿼리 · 수정 전후 각 1회. 판정은 "결과 1페이지에 `econ-blog.github.io`가 있는가".

| 쿼리 | 유형 | 이전 | 이후 | 1페이지를 차지한 것 |

| 쉽게 읽는 경제뉴스 econ-blog.github.io | 브랜드 | 없음 | 없음 | 한국경제·다음뉴스·무관한 GitHub Pages |
| 코픽스 뜻 변동금리 주담대 기준 | 정의형 | 없음 | 없음 | 토스뱅크·뱅크몰·파이낸셜뉴스 |

**0/4 → 0/4.** 이 결과는 구조적으로 그럴 수밖에 없다 — 수정은 아직 배포되지 않았고,
배포되더라도 크롤러 재방문과 색인에는 시간이 걸린다. 벤치마크의 값은 지금의 판정이 아니라
**배포 후 재실행할 때의 기준선**에 있다. 브랜드 쿼리에서조차 나오지 않는다는 것이 색인
2/60이라는 GSC 관측과 독립적으로 정합한다.

SERP 구성이 알려 주는 것: 뉴스형 쿼리는 통신사·일간지가 1페이지를 채우고 있어 36일 된
사이트가 비집고 들어갈 자리가 없다. 반면 정의형 쿼리는 토스뱅크·나무위키 같은 **비언론
설명 콘텐츠**가 상위를 잡는다. 이 사이트의 사전 28건이 경쟁 가능한 유일한 레인이고,
그래서 순위표 2·3위(FAQ·소제목)가 사전이 아니라 포스트를 대상으로 하더라도 사전 항목의
정의문 형태(P1)와 인바운드(L2)를 함께 봐야 한다.
