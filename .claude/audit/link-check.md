# ① 링크 무결성 + I 백필 스테이지 지침

발행된 글의 내부·외부 링크가 살아 있는지 확인하고, **확정 사망 링크만** 수정 변경안으로
만든다. 결과(리포트 섹션 텍스트 + 변경안)를 weekly-audit.md로 문자열로 넘긴다 — 파일 쓰기·
git은 시퀀서 §10이 한다. 모든 Python은 `.venv/bin/python`으로 호출한다.

이 스테이지의 불변조건(시퀀서와 이중으로 진술 — AC #39 규약): **git을 호출하지 않는다.
`source_url`을 수정·삭제하지 않는다(AC #11c). 연성 실패를 자동 수정 근거로 쓰지 않는다.**

## 1. 링크 인벤토리 수집
`content/**/*.md`의 링크를 모은다:
```
.venv/bin/python .claude/audit/lib/mdtext.py content/posts/*.md content/dictionary/*.md
```
출력 JSON에서 각 파일의 `internal`·`external`·`source_url`·`related_urls`를 얻는다.

## 2. 내부 링크 판정 (네트워크 없음, AC #6)
```
.venv/bin/python .claude/audit/lib/internal_links.py
```
`[]`가 아니면 각 항목을 **깨진 내부 링크**로 리포트에 싣는다. 이 검사는 결정론적이고
네트워크를 쓰지 않는다.

## 3. 외부 링크 조회 (AC #7·#8)

**이 단계에서 `linkcheck.py`를 실행하지 않는다.** 루틴 샌드박스는 뉴스 사이트에도
`econ-blog.github.io`에도 도달할 수 없다(설계 문서 §1.2). 여기서 실행하면 외부 URL 전건이
연결 실패 → `classify()`가 전부 `soft`로 분류 → `consecutive_soft_failures`가 올라가고
`manual_review`가 부풀어 **영속 원장에 가짜 실패가 커밋된다.** 감사를 하지 않는 것보다 나쁘다.

조회는 `fetch-linkstate.yml`이 일 01:37 KST에 미리 한다. 결과를 읽는다:

```
.venv/bin/python scripts/read_snapshot.py --subdir linkstate
```

`status`가 `ok`가 아니면 **① 전체를 `측정 안 함`으로 낸다.** 이 값은 §9-1 PR 본문 계약을
깨지 않는다 — `SUMMARY_LINE` 매처는 키 접두어만 보고 값은 자유다:

```
확정 사망 링크: 측정 안 함 / 사람 점검 필요: 측정 안 함
```

`ok`이면 스냅샷의 `summary`·`ledger`를 쓴다:

- `summary.ledger_was_stale`이 true면 리포트 최상단에 원장 정체 경고를 낸다(AC #13).
- `summary.confirmed_dead`가 **수정 대상**이다(하드 2회 + 5일 경과, AC #9).
- `manual_review`는 **사람 점검 필요** 섹션에, `moved`는 **이동됨** 섹션에 싣는다(둘 다
  자동 수정 대상 아님, AC #10·#7).
- `ledger`(갱신된 원장 전체)를 시퀀서 §10에 넘긴다. **§10이 그것을
  `.claude/audit/link-state.json`에 쓰고 커밋한다** — 원장의 쓰기 주체는 바뀌지 않았고,
  사람이 승인하는 PR을 여전히 거친다.

## 4. 확정 사망 링크 수정안 준비 (AC #11·#12)
`confirmed_dead`의 각 URL에 대해 그 URL이 어디서 왔는지로 변경안을 만든다. **변경안은
문자열로만 만들고 실제 쓰기·커밋은 시퀀서가 한다.**
- (a) **내부 링크**(§2에서 이미 깨짐으로 잡힌 것): 올바른 경로가 있으면 교정, 대상이
  없으면 **링크 마크업만 제거하고 앵커 텍스트는 남긴다**(`[기준금리](/x/)` → `기준금리`).
- (b) **`related_articles[].url`**: 해당 항목을 목록에서 제거한다. 목록이 비면
  `related_articles` 키 자체를 제거한다(빈 리스트를 남기지 않는다).
- (c) **`source_url`**: **어떤 경우에도 수정·삭제하지 않는다.** 죽었으면 리포트에만
  남긴다(AC #11c).
- 변경은 front matter의 `related_articles` 항목과 링크 마크업만 건드린다. 문장·단락을
  재작성하지 않는다(AC #12).

## 5. 백필 후보 탐지 (I, AC #62–67)
```
.venv/bin/python .claude/audit/lib/backfill.py
```
- `kind: "backfill"` 항목: 해당 파일의 그 줄에서 표면 문자열 **첫 등장 1회**를
  `[표면](/dictionary/<slug>/)`로 감싼다. **문서당 최대 3건, 전체 최대 20건**(초과분은
  다음 감사로). 변경은 링크 마크업뿐 — 산문을 재작성하지 않는다(AC #12·#67).
- `kind: "precedence"` 항목: **소견으로만** 낸다. 링크를 옮기거나 추가하지 않는다(AC #66).
- 백필 변경안도 확정 사망 링크와 **같은 PR**에 실리지만 리포트에서는 **별도 섹션**이다
  (AC #62). 콘텐츠 수정(확정 사망 및 백필)이 0건이면 콘텐츠 변경 파일 없이 리포트·원장만
  PR에 동봉한다. (I4 통일 규약)
- **에러 핸들링**: 어떠한 Python 헬퍼 호출이라도 exit != 0 또는 Traceback이 발생하면
  실행 결과를 무리하게 해석하지 말고 에러 메시지를 리포트 최상단 '계약 위반 및 시스템 에러'
  섹션에 그대로 출력한다. (I5 에러 가드)

## 리포트 조립 (시퀀서 §8·§9가 소비)
아래 섹션 텍스트를 만들어 시퀀서에 넘긴다. **소견은 위치·증거·제안·비용 4필드를 모두
갖춘 것만** 싣는다.

```
## ① 링크 무결성
- 검사한 외부 링크 N개(호스트 M개), 내부 링크 K개.

### 확정 사망 링크 (수정 대상)
| URL | 출처 위치 | 최근 2회 상태 | 최초 관측 | 수정안 |
(confirmed_dead 없으면 "- 없음")

### 사람 점검 필요 (연성 4주 연속)
| URL | 최근 4회 상태 | 최초 관측 |
(manual_review 없으면 생략)

### 이동됨 (리다이렉트, 자동 수정 안 함)
| 원 URL | 최종 URL |
(moved 없으면 생략)

### 깨진 내부 링크
| 파일 | 앵커 | 대상 |
(§2 결과 없으면 "- 없음")

## ① 확장: 내부 링크 백필
### 추가된 링크 (수정 PR 포함)
| 파일 | 표면 | slug | 줄 |
(backfill 0건이면 "- 후보 없음 (정상 — Known limits #22)")

### 선행 언급 (소견만, 이동 안 함)
| 파일 | 표면 | slug | 링크보다 앞선 줄 |
(precedence 0건이면 생략)
```

"확정 사망 링크 수정"과 "백필"은 **별도 섹션**으로 낸다 — 전자는 복구, 후자는 추가라
사람이 다른 눈으로 본다(AC #62).
