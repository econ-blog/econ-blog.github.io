# SEO/GEO 크롤 감사 스테이지 지침

렌더된 HTML을 훑어 여덟 축을 판정하고, **고칠 수 있는 것은 이 스테이지가 직접 고친다**.
결과(리포트 섹션 텍스트 + 수정 목록)를 `health-check.md`로 넘긴다.
모든 Python은 `.venv/bin/python` 전용.

주간 유지보수(`scripts/housekeeping.py`)와 겹치지 않는다 — 저쪽은 `content/` 마크다운을
읽고 이쪽은 **렌더 산출물**을 읽는다. 검색엔진과 답변엔진이 실제로 보는 것은 후자이며,
두 층이 어긋나는 결함(테마가 삼키는 메타, 부분 렌더되는 JSON-LD, 페이지네이션이 만드는
얕은 사본)은 마크다운 쪽에서는 원리적으로 보이지 않는다.

이 스테이지의 불변조건:

- **라이브 사이트에 도달하지 못한다.** 샌드박스에서 `econ-blog.github.io`는 연결되지
  않는다(설계된 제약). 크롤 대상은 로컬 빌드 산출물이다. 응답 헤더·실 HTTP 상태·CDN
  동작은 **측정하지 않았다고 적는다** — 측정한 것처럼 적지 않는다.
- **답변엔진에 직접 질의하지 못한다.** GEO는 결과(인용되었는가)가 아니라 입력(답변엔진이
  읽어 갈 수 있는 형태인가)으로 측정한다. 대리 지표임을 리포트에 명시한다.
- **쓰기 범위는 `health-check.md` §7이 정한 것뿐이다.** 본문 산문을 고치지 않는다.
- **정상 상태에서는 침묵한다.** 통과한 축을 나열하지 않는다.

## 1. 빌드

샌드박스에는 Hugo도 테마 서브모듈도 없다. 먼저 받는다:

```bash
bash scripts/bootstrap_sandbox.sh
export PATH="$HOME/.local/bin:$PATH"
git submodule update --init --depth 1 themes/PaperMod
hugo --environment production --destination /tmp/public
```

빌드가 실패하면 **이 스테이지 전체를 생략하고** ④ 중대 고장으로 올린다. 산출물이 없으면
아래 판정은 전부 근거가 없다.

## 2. 크롤 판정

```bash
.venv/bin/python scripts/seo_geo_audit.py /tmp/public --json /tmp/seo-geo.json
```

`findings` 배열이 판정 원문이다. 각 항목은 `axis`·`code`·`severity`·`count`·`items`.
표준 출력의 표를 리포트 섹션의 뼈대로 쓴다.

## 3. 결함 -> 처분

각 코드를 아래 표대로 처분한다. **표에 없는 코드는 소견으로만 남긴다** — 처분이 정해지지
않은 결함을 재량으로 고치지 않는다.

| 코드 | 결함 | 처분 |
|---|---|---|
| `T1` | 타이틀 35자 초과 | **고친다** — front matter `title` 단축(40자 규약 안에서 사이트명 접미사 11자를 감안). 변별 키워드는 앞에 남긴다. |
| `T3` | description 없음 | **고친다** — 본문 리드에서 핵심 팩트+결론 한 문장을 100자 내외로. |
| `T4` | description 길이 이탈 | **고친다** — 70~160자로. |
| `A3` | 옛 고정 H2 | **고친다** — H2 제목 줄만 주제어 포함 제목으로 바꾼다. 본문 문단은 건드리지 않는다. 고친 뒤 `headings.py`로 T4(제목 주제어 3/4)를 재확인한다. |
| `A5` | llms.txt 코퍼스 미포함 | **고친다** — `layouts/home.llms.txt` 템플릿의 범위. (2026-08-27 시점에는 이미 전량 렌더 중이므로 이 코드가 뜨면 템플릿 회귀다.) |
| `S3`·`S8` | BlogPosting에 `image`·`citation` 없음 | **고친다** — `layouts/_partials/templates/` 의 JSON-LD 템플릿에 필드를 추가한다. front matter의 `source_url`·`related_articles`가 이미 입력을 갖고 있다. |
| `S5` | FAQPage 없음 | front matter `faq` 2개가 있는데도 뜨면 **템플릿을 고친다**. `faq`가 비어서 뜨면 **고치지 않는다** — 본문 사실에서 답을 새로 쓰는 일이라 산문 작성에 해당한다. 소견으로 남긴다. |
| `L1`·`L2` | 본문 인바운드 0~1건 | **고친다** — 다른 글 본문에서 해당 용어에 내부 링크를 건다. 링크 앵커만 넣고 문장을 새로 쓰지 않는다. |
| `R2` | 1차 출처 링크 0건 | **고치지 않는다** — 어떤 지표의 어느 기준일 값인지는 원문 확인이 필요하다. 「기준일 확인」으로 §8 대기열에 올린다. |
| `I4` | 얇은 페이지(600자 미만) | **고치지 않는다** — 분량을 늘리는 것은 산문 작성이다. 소견. |
| `C3`·`C4` | 깨진 내부 링크 · 도달 불가 | **고친다** — 링크 경로 정정 또는 진입 경로 추가. |
| `T2` | 중복 타이틀 | **고친다** — 뒤에 발행된 쪽의 `title`을 변별되게 바꾼다. |
| `A1`·`A2`·`A4`·`A6`·`P1` | 리드·목록 서술 형태 | **고치지 않는다** — 전부 산문이다. 소견으로 남기고, 반복되면 `writing-styles.md` 개정 제안으로 올린다(파일은 loop이 소유하므로 「승인 필요」). |

`severity: high`부터 처리한다. `health-check.md` §7의 회차당 12파일 상한을 여기서 소진한다.

## 4. 반환

`health-check.md`로 돌려주는 것:

1. 리포트 `## SEO/GEO 크롤` 섹션 텍스트 — 크롤 기준선 표 + 판정 표 + (수정 후) 잔여 결함.
2. 이번 회차에 고친 파일 목록과 코드.
3. §8 대기열로 넘길 항목 (`R2` 기준일 확인, 승인 필요 건).
4. 다음 회차로 미룬 결함 수.
