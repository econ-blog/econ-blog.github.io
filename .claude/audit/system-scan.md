# ④ 시스템 스캔 스테이지 지침

닫힌 점검 축을 순회해 효율(E)·포스트 품질(Q)·수익성(P) 소견을 낸다. 결과를 문자열로
weekly-audit.md에 넘긴다 — 파일 쓰기·git은 시퀀서가 한다.

이 스테이지의 불변조건(시퀀서와 이중 진술 — AC #39 규약):
**추적 대상 파일(git이 추적하는 파일)을 수정하지 않는다(AC #34).** gitignore된 빌드
산출물(`public/`) 삭제는 예외다 — §1 E1 빌드 기준선이 `rm -rf public`을 요구하며,
`public/`은 추적 대상이 아니므로 이 불변조건과 충돌하지 않는다. CLAUDE.md의 낡은
카운트도, 미연결 용어도, 로드맵 불일치도 전부 소견으로만 낸다. `writing-styles.md`는
읽기만 하며 항목 **수만** 센다 — loop이 소유하고 `genre-diagnostic.md`가 "40~60자"
문자열을 falsification test용 load-bearing으로 지정했다. **git을 호출하지 않는다.**

모든 Python은 `.venv/bin/python`으로 호출한다. **닫힌 목록 밖은 보지 않는다** — 축을
늘리려면 SEED를 개정한다(AC #30).

## 0. 계약 검사 (E3) — 최우선
```
.venv/bin/python .claude/audit/lib/contracts.py
```
출력이 `[]`가 아니면 각 항목을 **계약 위반**으로 만든다. 계약 위반은 소견이 아니므로
**4필드(위치·증거·제안·비용) 규칙을 적용하지 않고**, 리포트 **최상단 전용 섹션**에
무조건 출력한다(AC #32). 줄 번호나 비용을 낼 수 없다는 이유로 드롭하지 않는다.

## 1. 효율 축 (E)

### E1 빌드 건전성
```
rm -rf public && hugo --gc --minify
```
- 종료 코드와 deprecation 경고 목록을 기록한다.
- 출력의 `Pages` / `Non-page files` 카운트를 기록한다. **감사 실행 전후로 동일한지만**
  검사한다 — 발행글이 늘면 카운트는 당연히 증가하므로 **고정 기댓값과 비교하지 않는다.**
  `--gc`는 고아 산출물을 지우지 않으므로 반드시 `rm -rf public`을 먼저 한다.
- `CLAUDE.md`는 더 이상 `Pages` 수를 고정하지 않는다. 대조 대상은 **`Non-page files == 1`**
  하나뿐이며(= `_terms.yaml`이 올바르게 제외되고 있다는 뜻), 이 값이 1이 아니면 소견으로 낸다.
  `Pages`는 기록만 하고 판정하지 않는다. 어느 경우에도 CLAUDE.md를 수정하지 않는다(AC #34·#38).

### E2 CI 건전성
```
gh run list --limit 10 --json conclusion,createdAt,displayTitle
```
읽기 전용이다. 실패율을 계산해 보고한다. `gh`가 인증되지 않았거나 실패하면 그 사실만
한 줄로 남기고 축을 건너뛴다(소견으로 만들지 않는다).

### E3 계약 검사
§0에서 이미 수행했다. 여기서는 다시 돌리지 않는다.

### E4 Hugo 버전 정합
```
hugo version
grep -n "HUGO_VERSION" .github/workflows/hugo.yml
```
로컬 버전(`hugo v0.164.0+extended...`의 `0.164.0`)과 워크플로의 `HUGO_VERSION` 값을
비교한다. 다르면 소견(위치 `.github/workflows/hugo.yml:25`, 증거 두 버전 문자열,
제안 로컬 업그레이드 또는 핀 갱신, 비용 S).

## 2. 포스트 품질 축 (Q)
```
.venv/bin/python .claude/audit/lib/quality.py
```
출력의 `Q1`·`Q3`·`Q4`·`Q5`·`P2`를 받는다.

- **Q1 front matter 완비**: `issues`가 있는 파일마다 소견. 위치 = 파일 경로, 증거 =
  결함 문자열, 제안 = 해당 필드 추가/길이 조정, 비용 S.
- **Q3 사전 미등재 용어 후보**: 빈도표에서 **경제 용어로 보이는 것만 최대 5건** 고른다.
  **이 선별은 LLM 판단이며 재현되지 않는다** — 리포트에 그 사실을 한 줄로 명시한다.
  **후보 1건 = 소견 1행**(5건을 한 행에 뭉치지 않는다). 각 소견은 위치·증거·제안·비용
  4필드를 갖춘다 — 위치 = 그 후보가 실제 등장한 포스트 경로를 나열(상위 5건까지 실제
  경로, 그 이상은 "외 K건"; `content/posts/` 같은 디렉터리 요약은 위치가 아니다), 증거 =
  등장 포스트 수·총 횟수, 제안 = `_terms.yaml` 등재 검토, 비용 M. **`_terms.yaml`에
  직접 추가하지 않는다** — 어휘 확장은 사람의 판단이다.
- **Q4 방치 초안**: 항목마다 소견(위치 = 파일, 증거 = 경과일, 제안 = 발행 또는 삭제
  결정, 비용 S).
- **Q5 자가검토 예산**: `{count, budget, remaining}`을 **관측치로만** 보고한다. 예산
  초과는 §0의 계약 위반이 이미 잡는다. 여기서 소견으로 승격하지 않는다.

### Q2 미연결 용어
```
.venv/bin/python .claude/audit/lib/backfill.py
```
`kind: "backfill"`과 `kind: "precedence"` 항목이 곧 Q2다 — **같은 계산이므로
재구현하지 않는다.** ①의 백필 섹션이 이미 이 결과를 싣고 있으면 Q2는 **"① 백필 섹션
참조"** 한 줄로 대신하고 중복 출력하지 않는다. Plan 1에서 백필이 제외된 상태라면
여기서 그 출력을 Q2 소견으로 낸다(위치 = 파일:줄, 증거 = 표면 문자열, 제안 = 링크
연결, 비용 S).

## 3. 수익성 축 (P)

### P1 AdSense 신청 준비도
- 정책 페이지 3종 존재 여부: `content/about.md`·`content/contact.md`·`content/privacy.md`
- 발행글 수: `.venv/bin/python .claude/audit/lib/corpus.py`의 `published_count`
- 방문자 추세: `.venv/bin/python scripts/fetch_ga4.py` (실패하면 그 사실만 한 줄)
세 값을 표로 낸다. **AdSense 수익 데이터 섹션은 만들지 않는다** — 미신청이므로 "데이터
없음" placeholder나 빈 표를 만들지 않는다(AC #24).

### P2 내부 순환
§2의 `P2` 값(포스트당 내부 링크 수·중앙값·무링크 포스트)을 표로 낸다. 무링크 포스트가
있으면 소견(위치 = 파일, 증거 = 링크 0건, 제안 = 관련 사전 항목 연결, 비용 S).
CLAUDE.md가 체류시간을 pre-AdSense 유일 신호로 못박았으므로 별도 축으로 본다.

### P3 유입 편중
```
.venv/bin/python scripts/fetch_ga4.py
```
출력의 `trafficSources`에서 상위 소스 비중을 계산해 **기술 통계로만** 보고한다.
**조정치로 환산하지 않는다.** 스크립트가 실패하거나 데이터가 비면 "GA4 데이터 없음"
한 줄로 끝낸다. 자격증명·서비스계정 이메일을 리포트에 쓰지 않는다(AC #41).

## 4. 로드맵 불일치 (AC #35)
`CLAUDE.md` 로드맵의 Agent3 설명("링크 체크, SEO, 디자인, 성능")과 SEED의 실제 범위
(① 링크 · ② 성과 · ③ 색인 · ④ 스캔 · ⑤ 방향 · ⑥ 수치, 그리고 Lighthouse·디자인·성능
자동 측정은 Out of scope)를 대조한다. 다르면 소견으로 낸다(위치 `CLAUDE.md` 로드맵
절, 증거 두 기술의 차이, 제안 로드맵 문구 갱신, 비용 S). **CLAUDE.md를 직접 수정하지
않는다.**

## 리포트 조립 (시퀀서가 소비)
두 덩어리를 따로 넘긴다.

**(A) 계약 위반 블록 — 리포트 최상단용.** 위반이 0건이면 이 블록을 생략한다.
```
## ⚠ 계약 위반
| 검사 | 내용 |
|---|---|
| 4필드 | draft.md에 '자산군별 함의'를 소비하는 지점이 없다 — … |
```

**(B) ④ 섹션.**
```
## ④ 시스템 스캔

### 효율 (E)
| 축 | 관측값 | 판정 |
| E1 빌드 | 종료 0, Pages N / Non-page M, 경고 K건 | … |
| E2 CI | 최근 10회 중 실패 K회 | … |
| E4 Hugo | 로컬 0.164.0 / CI 0.164.0 | 일치 |

### 포스트 품질 (Q)
| 축 | 관측값 |
| Q1 front matter | 결함 N건 |
| Q2 미연결 용어 | ① 백필 섹션 참조 (또는 N건) |
| Q3 미등재 용어 후보 | N건 (LLM 선별 — 재현되지 않음) |
| Q4 방치 초안 | N건 |
| Q5 자가검토 예산 | 7 / 12 (잔량 5) |

### 수익성 (P)
| 축 | 관측값 |
| P1 AdSense 준비도 | 정책 3/3, 발행 N건, 방문자 … |
| P2 내부 순환 | 포스트당 중앙값 X, 무링크 N건 |
| P3 유입 편중 | 상위 소스 비중 …% (기술 통계) |

### 소견
| # | 위치 | 증거 | 제안 | 비용 |
(4필드를 모두 갖춘 항목만. 없으면 "- 없음")
```

**소견 4필드 강제(AC #33)**: 위치·증거·제안·비용을 모두 갖추지 못한 항목은 싣지
않는다. "개선 여지가 있어 보인다" 류는 소견이 아니다. **값이 정상이라는 이유로 문장을
덧붙이지 않는다.**
