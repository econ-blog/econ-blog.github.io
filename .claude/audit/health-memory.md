# 격주 점검 장기 기억

이 파일은 `/health-check`가 **자기 자신에게 2주 뒤에 보내는 편지**다.

점검 세션은 격주로, 매번 빈 맥락에서 시작한다. `report/health-*.md`는 그때의 관측을
남기지만 그것은 사람이 읽는 문서다 — 무엇을 왜 시도했고, 무엇을 기대했고, 그래서
다음번에 무엇을 봐야 하는지는 거기 없다. 그게 여기 있다.

## 읽는 법 (매 회차 §1에서 가장 먼저)

```bash
.venv/bin/python scripts/health_memory.py tail --entries 3
.venv/bin/python scripts/health_memory.py stats
```

통째로 Read 하지 않는다. 회차가 쌓이면 잘려서 읽히고, **잘렸다는 사실은 티가 나지
않는다** — 그냥 "지난번에 별일 없었나 보다"가 된다.

## 쓰는 법 (매 회차 마지막)

```bash
cat <<'EOF' | .venv/bin/python scripts/health_memory.py append
## YYYY-MM-DD · 회차 N
...
EOF
```

같은 날짜로 두 번 쓰면 덮어쓴다(재실행은 회차를 늘리지 않는다). 첫 줄 형식이 틀리면
거부한다 — 형식이 무너지면 읽기도 같이 무너진다.

## 회차 하나의 형식

```markdown
## YYYY-MM-DD · 회차 N

### 지난 회차에서 넘어온 것
- [닫힘] H-2026-09-10-1 · 무엇을 했고 결과가 무엇이었나 · 판정 근거
- [계속] H-2026-09-10-2 · 왜 아직 결론이 안 났나 · 언제 결론 나나
- [폐기] H-... · 왜 버렸나

### 지금 사이트의 상태
발행 N건 / 색인 N건 / GSC 28일 클릭 N · 노출 N / 평균 게재순위 N
지난 회차 대비: 클릭 ±N · 색인 ±N
(숫자만 적는다. 해석은 아래에)

### 무엇을 알게 됐나
- 관측과 해석을 분리해서 쓴다. "노출은 3배인데 클릭이 그대로다"(관측) /
  "제목이 검색 결과에서 안 눌리는 것으로 보인다"(해석).

### 이번에 시도한 것
- H-YYYY-MM-DD-1 · <무엇을 바꿨나> · <왜 그게 효과가 있다고 봤나>
  · 기대: <무엇이 어떻게 달라지면 성공인가 — 숫자로>
  · 확인: <몇 회차 뒤에 무엇을 보고 판정하나>
  · 범위: <건드린 파일 수와 종류>

### 하지 않기로 한 것
- <무엇을> · <왜 지금은 아닌가> — 다음번 내가 같은 것을 또 검토하지 않도록.

### 다음 회차의 나에게
- 가장 먼저 볼 것 한 가지
- 조심할 것 (건드렸다가 되돌린 것, 부작용이 늦게 나올 만한 것)
- 사람에게 물어봐야 할지 고민 중인 것
```

## 가설 ID 규칙

`H-<시작한 회차 날짜>-<번호>`. 한 번 붙인 ID는 바꾸지 않는다 — 여러 회차에 걸쳐
같은 이름으로 추적되는 것이 이 원장의 목적이다. 판정은 `닫힘`(효과 확인) ·
`폐기`(효과 없음 또는 전제가 틀림) · `계속` 셋뿐이며, **판정하지 않고 조용히 사라지게
두지 않는다.** 어느 쪽으로든 결론이 나야 다음 시도가 그 위에 쌓인다.

## 압축

`stats`의 `compact_due`가 참이면(1200줄 초과) 그 회차에 압축한다. 최근 6회차는 그대로
두고, 그보다 오래된 회차는 **`## 굳은 기억` 절 하나로** 접는다 — 닫히거나 폐기된 가설의
결론, 반복해서 확인된 사실, 하지 않기로 한 것의 이유만 남기고 그때의 수치와 과정은
버린다. 오래된 회차의 원문이 필요하면 git 히스토리에 있다.
