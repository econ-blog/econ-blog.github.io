## 0. 모드 계약 (먼저 확인)
- **인자 없음 = 무인 모드**: AskUserQuestion 등 대화형 도구를 절대 호출하지 않는다.
  **리포트와 원장은 승인 없이 `main`에 직접 커밋·푸시한다** — 감사 산출물은 관측치이고
  사람이 반려할 대상이 아니다(2026-08-01 결정). **콘텐츠 수정(확정 사망 링크 수정 또는
  백필)이 1건 이상일 때만** 그 변경을 `auto/audit-YYYY-MM-DD` 브랜치 + PR로 분리한다.
  `content/`를 고치는 것은 여전히 사람이 승인한다.
- **인자 `manual` = 수동 모드**: 파이프라인은 동일하고, 콘텐츠 수정이 1건 이상이면
  마지막에 승인 게이트를 거쳐 `main`에 푸시한다.

이 계약을 이후 모든 단계에 적용한다. **git 브랜치 생성·커밋·PR은 이 시퀀서의 §10에서만
수행한다. 스테이지 파일(§2–§7)은 읽기·분석·리포트 작성까지만 하고 어떤 git 쓰기도 하지
않는다.** (AC #39)

모든 Python 호출은 `.venv/bin/python`으로 한다(시스템 python 금지). (AC #3)
Python 헬퍼 호출 중 스크립트가 비정상 종료(exit != 0 또는 Traceback 발생)하면, 해당
에러 메시지를 리포트 최상단 '계약 위반 및 시스템 에러' 섹션에 기록하고 콘텐츠 수정을
중단한다. (I5 에러 가드)

## 1. 사전 상태 가드 (AC #4)

**이 명령의 모든 `YYYY-MM-DD`는 KST 날짜다.** 리포트 파일명·브랜치명·커밋 제목이
전부 이 하나의 값을 쓴다. 맨 먼저 구해 놓고 이후 단계에서 다시 계산하지 않는다:

```bash
.venv/bin/python .claude/audit/lib/kstdate.py   # → YYYY-MM-DD (KST)
```

`date +%F`·`date.today()`를 쓰지 않는다. 샌드박스와 러너가 UTC로 돌아 일요일
05:00 KST 실행이 **전날** 날짜를 찍는다 — 2026-08-09 실행이 리포트를
`audit-2026-08-08.md`로 내보낸 것이 그 사고다. 스냅샷 파일명이 언제나 KST인 것과
같은 규약이며, `lib/*.py`가 원장에 찍는 날짜도 같은 헬퍼에서 나온다.

1. `git status`로 워킹 트리를 확인한다.
   - 더러우면: **무인 모드는 중단**(산출물 없음). 수동 모드는 사용자에게 알리고 확인을
     받는다.
2. 열려 있는 `auto/audit-*` PR이 있는지 확인한다. **루틴 샌드박스에는 `gh`가 없으므로
   `git ls-remote --heads origin 'auto/audit-*'`로 본다** — 병합되지 않은 브랜치가 곧
   미처리 콘텐츠 PR이다.
   - 있으면: 새 콘텐츠 수정 PR을 만들지 않고 **리포트·원장만 `main`에 올린다.** 리포트
     최상단에 "원장 정체 경고 — 이전 콘텐츠 PR 미병합, 2-strike 판정 불가"를 낸다.
     전체를 중단하지 않는다.
3. 오늘 날짜 브랜치 `auto/audit-YYYY-MM-DD`나 리포트 파일이 이미 존재하면 접미사
   `-HHMM`을 붙인다. (M4 파일명 충돌 예방) **`HHMM`도 KST 시각이다** —
   `TZ=Asia/Seoul date +%H%M`.

- **무인 모드**: 가설을 `채택`으로 올리지 않고 `제안`까지만 기록한다. 외부 가설 유입
  경로(스테이지 §4)를 실행하지 않는다. (AC #39·#48·#50)
- **수동 모드**: 스테이지 §7의 채택 승인 질문을 거친 것만 `채택`한다.
- ⑤는 `topic-report.md`를 **쓰지도 읽지도 않는다.** (AC #43)

## 8. 리포트 조립
`report/audit-YYYY-MM-DD[-HHMM].md`를 아래 골격으로 쓴다(형식은 §9 지침의 조립 규칙을
따른다). **`YYYY-MM-DD`는 §1에서 구한 KST 날짜다** — 여기서 다시 계산하지 않는다.
리포트는 `topic-report.md`와 **다른 파일**이며 형식 계약에 묶이지 않는다.

리포트 최상단 순서: (1) 계약 위반 전용 섹션 (2) 원장 정체 경고(링크 원장·방향 원장)
(3) "현재 방향" 블록(채택·확인대기 가설이 있을 때만) (4) 이후 ①②③④⑥⑤ 섹션.
"현재 방향"이 비면 블록 자체를 생략한다 — placeholder를 만들지 않는다. (AC #48)

골격은 섹션 헤딩 순서만 고정한다(각 섹션 내부 서식은 §9·해당 스테이지 지침을 따른다):
1. (있으면) `## ⚠ 계약 위반` — 아래 문단 참조, 항상 최상단
2. (있으면) `## 현재 방향` — 채택·확인대기 가설
3. `## ① 링크 무결성`
4. `## ① 확장: 내부 링크 백필`
5. `## ② 성과 분석`
6. (있으면) `## ③ 색인 건전성` — 단계가 "정상"이면 ③은 H2 없이 한 줄 또는 `### 소견`만
   낸다. 그 경우 이 항목을 만들지 않는다.
7. `## ④ 시스템 스캔`
8. `## ⑥ 수치 무결성`
9. `## ⑤ 방향성 점검`
10. (있으면) `## 로컬 세션 대기열` — §9-2가 `로컬 세션`으로 가른 항목. 0건이면 섹션을 생략한다

**`## 로컬 세션 대기열`은 새 파일을 만들지 않는다.** 리포트 안의 한 섹션이며, §10-1의
산출물 다섯 개는 그대로다. `/audit-local`이 가장 최근 `report/audit-*.md`에서 이 섹션을
읽어 작업 목록으로 쓴다 — 두 명령이 같은 문자열을 보므로 헤딩을 바꾸면 양쪽을 함께 고친다.

각 항목은 `- [ ] <축> · <대상> · <확인할 것> · <확인 뒤 할 일>` 한 줄로 쓴다. 체크박스를
쓰는 것은 로컬 세션이 처리한 것을 그 자리에 표시해 다음 주 감사가 중복해서 올리지 않게
하기 위해서다.

**계약 위반은 리포트 최상단이다(AC #32).** ④가 (A) 블록을 돌려줬으면 위 골격의 다른 어떤
섹션보다 먼저 배치한다. 4필드 규칙을 적용하지 않으며, 줄 번호·비용을 낼 수 없다는 이유로
드롭하지 않는다. 위반이 0건이면 블록 자체를 생략한다 — "위반 없음" placeholder를 만들지
않는다.

## 9. 리포트 형식 규칙
스테이지가 돌려준 소견은 **위치·증거·제안·비용 4필드**를 모두 갖춘 것만 싣는다. 계약
위반(Python 에러 포함)은 최상단 전용 섹션에 무조건 출력한다. 상세 규칙은 link-check.md
§리포트 조립을 따른다.

## 9-1. 감사 요약 블록 (커밋 메시지 본문)

무인 모드에서 이 블록은 §10-3의 `main` 커밋 메시지 본문이 된다. 콘텐츠 수정 PR(§10-4)에는 쓰지 않는다. §9-1의 여덟 줄 블록을 커밋
메시지 본문에 넣되, **`--cleanup=verbatim`을 반드시 명시한다.** `#` 줄이 지워지면 텔레그램 요약이
통째로 사라지므로 생략할 수 없다. `scripts/telegram_notify.py`의 `format_audit_notification`이
PR 본문을 줄 단위로 필터링해 텔레그램 요약을 만들며, **아래 여덟 줄의 문자열이 축자로 일치하지
않으면 그 줄은 알림에서 통째로 사라진다.** 리포트 본문의 H2 헤딩(`## ⚠ 계약 위반` 등)은
콜론이 없어 매칭되지 않는다 — 리포트와 PR 본문은 **다른 형식**이다.

본문 첫 블록을 정확히 이 형태로 쓴다(값만 채운다. 줄을 지우거나 순서를 바꾸지 않는다):

```
## 감사 요약
계약 위반: N건
확정 사망 링크: N건 / 사람 점검 필요: N건
데이터 충분성: 미달 (발행 N / 20건)
색인 건전성: 정상
소견: N건 (④ N, ⑥ N)
front matter 수정: N건
새 가설 제안: N건
─ 결정 필요 ─
* <사람 판단이 필요한 항목 한 줄>
PR 리포트: report/audit-YYYY-MM-DD[-HHMM].md
```

각 값의 출처는 이미 계산된 것을 그대로 옮긴다 — **여기서 다시 세지 않는다.**

| 줄 | 값의 출처 |
|---|---|
| `계약 위반:` | §5가 돌려준 (A) 블록의 항목 수. 0건이면 `0건`으로 적는다(리포트와 달리 줄을 생략하지 않는다) |
| `확정 사망 링크:` / `사람 점검 필요:` | §2 링크 무결성 |
| `데이터 충분성:` | §3. 게이트 통과 시 `통과`, 미달이면 `미달 (발행 N / 20건)` |
| `색인 건전성:` | §4의 단계 문자열 하나 — `정상` · `관찰` · `소견`(`indexation.py`의 `tier`가 내는 어휘 그대로). ③을 생략했으면 `측정 안 함` |
| `소견:` | §5(④)·§6(⑥)이 낸 4필드 소견의 합계와 축별 내역. **⑤의 소견은 이 줄에 넣지 않는다** — 형식이 `(④ N, ⑥ N)`으로 고정이라 자리가 없다 |
| `front matter 수정:` | §5(④)가 낸 (C) 블록의 항목 수. 0건이면 `0건`으로 적는다 — 줄을 생략하지 않는다 |
| `새 가설 제안:` | §7이 `제안`으로 기록한 건수 |
| `─ 결정 필요 ─` 이하 | **§9-2가 `사람 판정`으로 가른 항목만.** 없으면 헤더 줄만 남기고 `* 없음`을 적는다 |

리포트 본문 전체를 PR 본문에 복사하지 않는다 — 텔레그램 메시지 길이 제한(4096자)에
걸리고, 필터를 통과하지 못하는 줄이 대부분이다.

## 9-2. 소견을 `Claude 판정` / `사람 판정` / `로컬 세션`으로 가른다

모든 소견은 리포트에 실리기 전에 아래 셋 중 하나로 표시된다. 표시가 없는 소견은
리포트에 싣지 않는다 — 분류되지 않은 소견은 매주 같은 자리에 되살아나 사람의 주의를
소모하기만 한다.

**판별은 두 질문 순서대로 한다. 항목 목록을 외우는 것이 아니다.**

1. **판정 근거가 이 저장소 안에서 닫히는가?** — 저장소의 파일과 결정론적 규칙만으로
   답이 정해지면 `Claude 판정`이다. 저장소 밖의 사실이 필요하면 2번으로 간다.
2. **저장소 밖의 그 사실을 이 세션이 확인할 수 있는가?** — 클라우드 샌드박스의 egress는
   GitHub 계열 + PyPI + npm뿐이고 WebFetch는 동작하지 않는다(`AGENTS.md` 자동화 평면).
   확인 경로가 없으면 `로컬 세션`이다. 확인은 가능하지만 **선택**이 필요한 것 —
   무엇을 옳다고 볼지가 사실이 아니라 정책인 것 — 은 `사람 판정`이다.

| 표시 | 뜻 | 이 감사가 하는 일 |
|---|---|---|
| `Claude 판정` | 규칙이 닫혀 있어 판정이 재현된다 | 그 자리에서 고치고 `auto/audit-*` PR에 담는다. 결정 필요 블록에 올리지 않는다 |
| `사람 판정` | 사실이 아니라 정책·우선순위 선택이다 | 고치지 않는다. §9-1 `─ 결정 필요 ─`에 한 줄로 올린다 |
| `로컬 세션` | 사실 확인이 필요한데 이 샌드박스가 도달하지 못한다 | 고치지 않는다. 리포트의 `## 로컬 세션 대기열` 섹션에 싣는다 |

### 이번 축들이 어디로 가는가 (2026-08-16 분류)

판별 질문의 적용 예다. **이 표를 근거로 새 판정을 만들지 않는다** — 위 두 질문이 권위이고,
새로운 축이 생기면 표가 아니라 질문에 물어본다.

| 축 | 표시 | 이유 |
|---|---|---|
| ① 확정 사망 링크(2-strike 원장) | Claude 판정 | 원장이 저장소 안에 있고 규칙이 닫혀 있다 |
| ① 내부링크 백필 | Claude 판정 | `_terms.yaml` 대조. 결정론 |
| ① 러너 도달 불가 의심 | 로컬 세션 | 러너 IP에서만 막힌 것인지 실제 사망인지 다른 네트워크에서 열어 봐야 갈린다 |
| ② `topic-report.md` 조정치 | 사람 판정 | `rank.md` 채점에 직접 들어간다. 파급이 가장 크다 |
| ③ 색인 요청 제출 | 로컬 세션 | GSC·네이버 로그인 브라우저가 필요하다 |
| ③ I3·I4(baseURL·sitemap) | Claude 판정 | 설정 파일 대조 |
| ④ Q1 front matter 결함 | Claude 판정 | 길이·존재 검사 |
| ④ 계약 위반·Python 에러 | Claude 판정 | 실행 결과가 곧 판정이다 |
| ⑤ D4 1차 출처 소급 링크 | 로컬 세션 | 붙일 URL이 실재하는지 열어 봐야 안다. 지어내면 다음 주 ①이 사망 링크로 잡는다 |
| ⑤ 가설 `채택` | 사람 판정 | 무인 모드는 `제안`까지만(§7) |
| ⑤ 측정 정의가 다른 규칙과 모순 | Claude 판정 | 두 파일을 읽어 대조하면 나온다. 단, **고치기 전에 어느 쪽이 최신 결정인지 `AGENTS.md`에서 확인한다** |
| ⑥ N2·N4·N5 | Claude 판정 | 호스트 목록 대조·닫힌 최상급 목록·사전↔포스트 값 대조 전부 결정론 |
| ⑥ N1 — 기준일이 **같은 문서 안**에 있는 경우 | Claude 판정 | front matter `date`, 같은 절의 다른 문장, 링크된 과거 글에서 확인된다 |
| ⑥ N1 — 기준일이 **원문 기사에만** 있는 경우 | 로컬 세션 | 날짜를 지어내는 것이 위반보다 나쁘다 |

| 로드맵·감사 범위 변경 | 사람 판정 | `AGENTS.md` 로드맵 절이 최종 권위이며 에이전트가 고치지 못한다 |

**`사람 판정`을 `Claude 판정`으로 올리지 않는다.** 판정이 어려워서가 아니라 **틀렸을 때
되돌리는 비용이 크기 때문에** 사람에게 있는 항목들이다. 특히 ②의 조정치와 호스트 목록은
한 번 틀리면 그 뒤 몇 주의 채점이 전부 그 값 위에서 이뤄진다.

## 10. 게시 (git은 여기서만)
- **무인 모드**: `draft`/게시 개념이 없다 — 리포트와 원장은 항상 쓴다. **경로가 둘로
  갈린다: 리포트·원장은 `main` 직행, `content/` 수정은 PR.**

  1. 리포트 `report/audit-YYYY-MM-DD[-HHMM].md`와 원장
     `.claude/audit/link-state.json`·`.claude/audit/direction-log.json`을 명시적으로
     `git add`한다(글롭 금지). **②가 게이트를 통과했을 때만** `.claude/audit/topic-report.md`와
     `.claude/audit/topic-history.json`을 쓰고 add한다 — 미충족이면 두 파일에 손대지
     않는다(AC #21). 이 다섯이 AC #36의 산출물 전부이며 여섯 번째 파일을 만들지 않는다.
     **`content/` 파일은 여기서 add하지 않는다.**
  2. `git status`로 다른 변경이 섞이지 않았는지 확인한다.
  3. **`main`에서 바로 커밋·푸시한다.** 브랜치를 만들지 않는다.

     ```
     git commit --cleanup=verbatim -m "audit: YYYY-MM-DD 주간 감사" -m "<§9-1 본문>"
     git push origin main
     ```

     `--cleanup=verbatim`은 유지한다 — §9-1 본문이 `## 감사 요약`으로 시작하므로 `#` 줄이
     지워지면 요약이 통째로 사라진다. **이 커밋이 텔레그램 리포트 알림을 띄운다**:
     `notify-audit-report.yml`이 `main`의 `report/audit-*.md` push를 받아 이 커밋 본문을
     그대로 요약으로 쓴다. §9-1 블록이 깨지면 알림이 "요약 정보 없음"으로 나간다 —
     `notify.yml`(PR 경로)과 **같은 필터**(`summarize_audit_body`)를 통과하므로 줄 형식을
     한쪽만 바꾸지 않는다. 이 알림은 승인 대상이 아니며 판정 토큰도 붙지 않는다.
  4. **콘텐츠 수정이 1건 이상일 때만** 그것만 담아 `auto/audit-YYYY-MM-DD[-HHMM]` 브랜치를
     만들어 커밋·푸시한다. 콘텐츠 수정은 셋이다 — 확정 사망 링크 수정 · 내부링크 백필 ·
     ④가 넘긴 **(C) front matter 수정안 적용**. (C)를 적용할 때는 해당 파일의 front matter
     **그 필드 한 줄만** 바꾼다. 본문은 한 글자도 건드리지 않는다. **`gh`를 호출하지
     않는다** — 루틴 샌드박스에 `gh` 자격증명 경로가 없다. PR은
     `.github/workflows/open-auto-pr.yml`이 push를 받아 만들고 **커밋 메시지 본문을 그대로
     PR 본문으로 쓴다.** 이 PR은 `content/` 변경만 담으며 리포트·원장은 이미 §10-3에서
     `main`에 올라가 있다. 커밋 메시지 본문에는 어떤 파일을 왜 고쳤는지(URL·실패 이력, front matter는 필드명과
     현재값→제안값)를 적는다. **description 제안값은 LLM 산출물이라 결정론이 아니다** —
     본문과 어긋나지 않는지가 사람이 이 PR에서 볼 것이며, 그 사실을 PR 본문에 한 줄로 적는다.
  5. 콘텐츠 수정이 0건이면 §10-4를 건너뛴다. Q1 결함이 남아 있는 동안은 통상 상태가 아니다.
- **수동 모드**: 링크 수정이 1건 이상이면 (a) 변경 파일 경로 (b) 각 링크의 실패 이력
  (2회 관측 날짜·상태코드)을 상위 10건까지 상세히, 나머지는 "외 N건"으로 제시하고
  "이 링크들을 수정해 main에 푸시할까요?"로 승인을 구한다.
  front matter 수정안이 1건 이상이면 파일 경로·필드·현재값·제안값을 표로 제시하고
  링크 수정과 **함께** 승인을 구한다. 승인 질문을 나누지 않는다 — 같은 PR로 나간다.
  `topic-report.md`가 갱신되는 경우, 승인 질문에 **주제군별 최종 조정치와 그 근거
  (`r_g`·강등·감쇄)** 를 함께 제시한다. 이 파일은 `rank.md`의 채점에 직접 들어가므로
  링크 수정보다 파급이 크다.
  명확한 긍정만 승인으로 인정한다. 승인 후에만 `git add`(명시 경로) → `git commit` → `git push origin main`.
  승인 전에는 어떤 git 쓰기도 하지 않는다. 링크 수정이 0건이면 리포트·원장을
  `main`에 바로 커밋하되, 이 역시 사용자에게 먼저 알린다.
