## 0. 모드 계약 (먼저 확인)
- **인자 없음 = 무인 모드**: AskUserQuestion 등 대화형 도구를 절대 호출하지 않는다.
  **리포트와 원장은 승인 없이 `main`에 직접 커밋·푸시한다** — 감사 산출물은 관측치이고
  사람이 반려할 대상이 아니다(2026-08-01 결정). **콘텐츠 수정(확정 사망 링크 수정 또는
  백필)이 1건 이상일 때만** 그 변경을 `auto/audit-YYYY-MM-DD` 브랜치 + PR로 분리한다.
  `content/`를 고치는 것은 여전히 사람이 승인한다.
- **인자 `manual` = 수동 모드**: 파이프라인은 동일하고, 콘텐츠 수정이 1건 이상이면
  마지막에 승인 게이트를 거쳐 `main`에 푸시한다.

이 계약을 이후 모든 단계에 적용한다. **git 브랜치 생성·커밋·PR은 이 시퀀서의 §10에서만
수행한다. 스테이지 파일(§2–§7)은 읽기·분석·리포트 작성까지만 하고 어떤 git 쓰기도 하지
않는다.** (AC #39)

모든 Python 호출은 `.venv/bin/python`으로 한다(시스템 python 금지). (AC #3)
Python 헬퍼 호출 중 스크립트가 비정상 종료(exit != 0 또는 Traceback 발생)하면, 해당
에러 메시지를 리포트 최상단 '계약 위반 및 시스템 에러' 섹션에 기록하고 콘텐츠 수정을
중단한다. (I5 에러 가드)

## 1. 사전 상태 가드 (AC #4)
1. `git status`로 워킹 트리를 확인한다.
   - 더러우면: **무인 모드는 중단**(산출물 없음). 수동 모드는 사용자에게 알리고 확인을
     받는다.
2. 열려 있는 `auto/audit-*` PR이 있는지 확인한다. **루틴 샌드박스에는 `gh`가 없으므로
   `git ls-remote --heads origin 'auto/audit-*'`로 본다** — 병합되지 않은 브랜치가 곧
   미처리 콘텐츠 PR이다.
   - 있으면: 새 콘텐츠 수정 PR을 만들지 않고 **리포트·원장만 `main`에 올린다.** 리포트
     최상단에 "원장 정체 경고 — 이전 콘텐츠 PR 미병합, 2-strike 판정 불가"를 낸다.
     전체를 중단하지 않는다.
3. 오늘 날짜 브랜치 `auto/audit-YYYY-MM-DD`나 리포트 파일이 이미 존재하면 접미사
   `-HHMM`을 붙인다. (M4 파일명 충돌 예방)

## 8. 리포트 조립
`report/audit-YYYY-MM-DD[-HHMM].md`를 아래 골격으로 쓴다(형식은 §9 지침의 조립 규칙을
따른다). 리포트는 `topic-report.md`와 **다른 파일**이며 형식 계약에 묶이지 않는다.

리포트 최상단 순서: (1) 계약 위반 전용 섹션 (2) 원장 정체 경고(링크 원장·방향 원장)
(3) "현재 방향" 블록(채택·확인대기 가설이 있을 때만) (4) 이후 ①②③④⑥⑤ 섹션.
"현재 방향"이 비면 블록 자체를 생략한다 — placeholder를 만들지 않는다. (AC #48)

골격은 섹션 헤딩 순서만 고정한다(각 섹션 내부 서식은 §9·해당 스테이지 지침을 따른다):
1. (있으면) `## ⚠ 계약 위반` — 아래 문단 참조, 항상 최상단
2. (있으면) `## 현재 방향` — 채택·확인대기 가설
3. `## ① 링크 무결성`
4. `## ① 확장: 내부 링크 백필`
5. `## ② 성과 분석`
6. (있으면) `## ③ 색인 건전성` — 단계가 "정상"이면 ③은 H2 없이 한 줄 또는 `### 소견`만
   낸다. 그 경우 이 항목을 만들지 않는다.
7. `## ④ 시스템 스캔`
8. `## ⑥ 수치 무결성`
9. `## ⑤ 방향성 점검`

**계약 위반은 리포트 최상단이다(AC #32).** ④가 (A) 블록을 돌려줬으면 위 골격의 다른 어떤
섹션보다 먼저 배치한다. 4필드 규칙을 적용하지 않으며, 줄 번호·비용을 낼 수 없다는 이유로
드롭하지 않는다. 위반이 0건이면 블록 자체를 생략한다 — "위반 없음" placeholder를 만들지
않는다.

## 9. 리포트 형식 규칙
스테이지가 돌려준 소견은 **위치·증거·제안·비용 4필드**를 모두 갖춘 것만 싣는다. 계약
위반(Python 에러 포함)은 최상단 전용 섹션에 무조건 출력한다. 상세 규칙은 link-check.md
§리포트 조립을 따른다.

## 9-1. 감사 요약 블록 (커밋 메시지 본문)

무인 모드에서 이 블록은 §10-3의 `main` 커밋 메시지 본문이 된다. 콘텐츠 수정 PR(§10-4)에는 쓰지 않는다. §9-1의 일곱 줄 블록을 커밋
메시지 본문에 넣되, **`--cleanup=verbatim`을 반드시 명시한다.** `#` 줄이 지워지면 텔레그램 요약이
통째로 사라지므로 생략할 수 없다. `scripts/telegram_notify.py`의 `format_audit_notification`이
PR 본문을 줄 단위로 필터링해 텔레그램 요약을 만들며, **아래 일곱 줄의 문자열이 축자로 일치하지
않으면 그 줄은 알림에서 통째로 사라진다.** 리포트 본문의 H2 헤딩(`## ⚠ 계약 위반` 등)은
콜론이 없어 매칭되지 않는다 — 리포트와 PR 본문은 **다른 형식**이다.

본문 첫 블록을 정확히 이 형태로 쓴다(값만 채운다. 줄을 지우거나 순서를 바꾸지 않는다):

```
## 감사 요약
계약 위반: N건
확정 사망 링크: N건 / 사람 점검 필요: N건
데이터 충분성: 미달 (발행 N / 20건)
색인 건전성: 정상
소견: N건 (④ N, ⑥ N)
새 가설 제안: N건
─ 결정 필요 ─
* <사람 판단이 필요한 항목 한 줄>
PR 리포트: report/audit-YYYY-MM-DD[-HHMM].md
```

각 값의 출처는 이미 계산된 것을 그대로 옮긴다 — **여기서 다시 세지 않는다.**

| 줄 | 값의 출처 |
|---|---|
| `계약 위반:` | §5가 돌려준 (A) 블록의 항목 수. 0건이면 `0건`으로 적는다(리포트와 달리 줄을 생략하지 않는다) |
| `확정 사망 링크:` / `사람 점검 필요:` | §2 링크 무결성 |
| `데이터 충분성:` | §3. 게이트 통과 시 `통과`, 미달이면 `미달 (발행 N / 20건)` |
| `색인 건전성:` | §4의 단계 문자열 하나 — `정상` · `관찰` · `소견`(`indexation.py`의 `tier`가 내는 어휘 그대로). ③을 생략했으면 `측정 안 함` |
| `소견:` | §5(④)·§6(⑥)이 낸 4필드 소견의 합계와 축별 내역. **⑤의 소견은 이 줄에 넣지 않는다** — 형식이 `(④ N, ⑥ N)`으로 고정이라 자리가 없다 |
| `새 가설 제안:` | §7이 `제안`으로 기록한 건수 |
| `─ 결정 필요 ─` 이하 | 사람이 판정해야 승인/반려가 갈리는 항목만. 없으면 헤더 줄만 남기고 `* 없음`을 적는다 |

리포트 본문 전체를 PR 본문에 복사하지 않는다 — 텔레그램 메시지 길이 제한(4096자)에
걸리고, 필터를 통과하지 못하는 줄이 대부분이다.

## 10. 게시 (git은 여기서만)
- **무인 모드**: `draft`/게시 개념이 없다 — 리포트와 원장은 항상 쓴다. **경로가 둘로
  갈린다: 리포트·원장은 `main` 직행, `content/` 수정은 PR.**

  1. 리포트 `report/audit-YYYY-MM-DD[-HHMM].md`와 원장
     `.claude/audit/link-state.json`·`.claude/audit/direction-log.json`을 명시적으로
     `git add`한다(글롭 금지). **②가 게이트를 통과했을 때만** `.claude/audit/topic-report.md`와
     `.claude/audit/topic-history.json`을 쓰고 add한다 — 미충족이면 두 파일에 손대지
     않는다(AC #21). 이 다섯이 AC #36의 산출물 전부이며 여섯 번째 파일을 만들지 않는다.
     **`content/` 파일은 여기서 add하지 않는다.**
  2. `git status`로 다른 변경이 섞이지 않았는지 확인한다.
  3. **`main`에서 바로 커밋·푸시한다.** 브랜치를 만들지 않는다.

     ```
     git commit --cleanup=verbatim -m "audit: YYYY-MM-DD 주간 감사" -m "<§9-1 본문>"
     git push origin main
     ```

     `--cleanup=verbatim`은 유지한다 — §9-1 본문이 `## 감사 요약`으로 시작하므로 `#` 줄이
     지워지면 요약이 통째로 사라진다. **이 경로에는 PR이 없으므로 텔레그램 알림도 없다**
     (`notify.yml`은 `auto/**` push에만 반응한다). §9-1 블록은 커밋 메시지에 그대로 남겨
     `git log`가 요약을 담게 한다.
  4. **콘텐츠 수정(확정 사망 링크 수정 및 백필)이 1건 이상일 때만** 그것만 담아
     `auto/audit-YYYY-MM-DD[-HHMM]` 브랜치를 만들어 커밋·푸시한다. **`gh`를 호출하지
     않는다** — 루틴 샌드박스에 `gh` 자격증명 경로가 없다. PR은
     `.github/workflows/open-auto-pr.yml`이 push를 받아 만들고 **커밋 메시지 본문을 그대로
     PR 본문으로 쓴다.** 이 PR은 `content/` 변경만 담으며 리포트·원장은 이미 §10-3에서
     `main`에 올라가 있다. 커밋 메시지 본문에는 어떤 파일을 왜 고쳤는지(URL·실패 이력)를
     적는다 — §9-1 블록은 감사 요약이므로 여기 쓰지 않는다.
  5. 콘텐츠 수정이 0건이면 §10-4를 건너뛴다. 그것이 통상 상태다.
- **수동 모드**: 링크 수정이 1건 이상이면 (a) 변경 파일 경로 (b) 각 링크의 실패 이력
  (2회 관측 날짜·상태코드)을 상위 10건까지 상세히, 나머지는 "외 N건"으로 제시하고
  "이 링크들을 수정해 main에 푸시할까요?"로 승인을 구한다.
  `topic-report.md`가 갱신되는 경우, 승인 질문에 **주제군별 최종 조정치와 그 근거
  (`r_g`·강등·감쇄)** 를 함께 제시한다. 이 파일은 `rank.md`의 채점에 직접 들어가므로
  링크 수정보다 파급이 크다.
  명확한 긍정만 승인으로 인정한다. 승인 후에만 `git add`(명시 경로) → `git commit` → `git push origin main`.
  승인 전에는 어떤 git 쓰기도 하지 않는다. 링크 수정이 0건이면 리포트·원장을
  `main`에 바로 커밋하되, 이 역시 사용자에게 먼저 알린다.
