## 0. 모드 계약 (먼저 확인)
- **인자 없음 = 무인 모드**: AskUserQuestion 등 대화형 도구를 절대 호출하지 않는다.
  `auto/audit-YYYY-MM-DD` 브랜치에 커밋·푸시하고 PR을 만든다. `main`에 직접 푸시하지
  않는다. 리포트·원장 PR은 매 실행마다 항상 생성하되, 콘텐츠 수정(확정 사망 링크 수정
  또는 백필)은 해당 변경안이 1건 이상 있을 때만 동봉한다. (I4 통일 규약)
- **인자 `manual` = 수동 모드**: 파이프라인은 동일하고, 콘텐츠 수정이 1건 이상이면
  마지막에 승인 게이트를 거쳐 `main`에 푸시한다.

이 계약을 이후 모든 단계에 적용한다. **git 브랜치 생성·커밋·PR은 이 시퀀서의 §10에서만
수행한다. 스테이지 파일(§2–§7)은 읽기·분석·리포트 작성까지만 하고 어떤 git 쓰기도 하지
않는다.** (AC #39)

모든 Python 호출은 `.venv/bin/python`으로 한다(시스템 python 금지). (AC #3)
Python 헬퍼 호출 중 스크립트가 비정상 종료(exit != 0 또는 Traceback 발생)하면, 해당
에러 메시지를 리포트 최상단 '계약 위반 및 시스템 에러' 섹션에 기록하고 콘텐츠 수정을
중단한다. (I5 에러 가드)

## 1. 사전 상태 가드 (AC #4)
1. `git status`로 워킹 트리를 확인한다.
   - 더러우면: **무인 모드는 중단**(산출물 없음). 수동 모드는 사용자에게 알리고 확인을
     받는다.
2. 열려 있는 `auto/audit-*` PR이 있는지 `gh pr list --state open --search "head:auto/audit"`로 확인한다.
   - 있으면: 링크 수정 PR을 만들지 않고 **리포트만 생성**한다. 리포트 최상단에
     "원장 정체 경고 — 이전 감사 PR 미병합, 2-strike 판정 불가"를 낸다. 전체를 중단하지
     않는다.
3. 오늘 날짜 브랜치 `auto/audit-YYYY-MM-DD`나 리포트 파일이 이미 존재하면 접미사
   `-HHMM`을 붙인다. (M4 파일명 충돌 예방)

## 2. ① 링크 무결성 + I 백필
`.claude/audit/link-check.md`를 Read로 읽고 그 지침에 따라 링크 검사·백필 후보 탐지를
수행한다. 스테이지는 `lib/*.py`를 호출해 결과를 모으고, 리포트 섹션 텍스트와 (있으면)
링크 수정·백필 변경안을 **문자열로만** 이 시퀀서에 돌려준다. 파일 쓰기·git은 하지 않는다.

## 3. ② 성과 분석
`.claude/audit/performance.md`를 Read로 읽고 그 지침에 따라 게이트를 판정한다.

- 스테이지가 돌려줄 것: (가) ② 리포트 섹션 (나) `published_count`·`site_age`
  (다) **게이트를 통과했을 때만** `topic-report.md` 내용과 갱신된
  `topic-history.json` 내용. 전부 문자열이며 파일 쓰기·git은 §10이 한다.
- **게이트 미충족이면 `topic-report.md`를 생성·수정·삭제하지 않는다.** 기존 파일이
  있으면 그대로 둔다. 2026-07-26 기준 세 조건 전부 미달이며 그 상태가 정상이다. (AC #21)
- (나)의 두 값을 §4와 §7에 그대로 넘긴다 — **각 단계가 다시 계산하지 않는다.**
- 조정치는 `attribution.adjustment`의 표로만 산출한다. 시퀀서가 숫자를 보정하지
  않는다. (AC #17)
- AdSense 미신청이므로 수익 섹션을 통째로 생략한다. (AC #24)

## 4. ③ 색인 건전성
`.claude/audit/indexation.md`를 Read로 읽고 그 지침에 따라 색인 상태를 판정한다.
§3이 넘긴 `site_age`를 쓴다.

- `scripts/fetch_gsc.py`가 없으면 ③ 전체를 생략한다. (AC #26)
- `site_age < 14`이면 **노출 0을 보고하지 않고 한 줄만** 낸다. `14 ≤ D < 42`는 표만,
  `D ≥ 42`는 4필드 소견. (AC #27·#29)
- **I3(baseURL 3자 정합)·I4(sitemap 미제출)는 단계와 무관하게 즉시 소견이다.** (AC #28)
- ③은 무엇도 고치지 않는다. sitemap 제출·속성 재등록·색인 요청은 사용자가 Search
  Console에서 직접 한다.

## 6. ⑥ 수치 무결성

⑥은 **읽기 전용·무상태**다 — 어떤 파일도 수정하지 않고 원장도 남기지 않는다(AC #61).

## 7. ⑤ 방향성 점검
`.claude/audit/direction-review.md`를 Read로 읽고 그 지침에 따라 포트폴리오 축 D1–D6을
측정하고 가설을 대조·제안한다. **⑤는 마지막 분석 단계다** — §3·§4의 ②③ 판정 결과와
§5의 소견 목록을 입력으로 받는다(AC #42).

- ②가 게이트에 막혀 침묵해도 **⑤는 정상 실행된다.** 포트폴리오 축은 트래픽 API를 쓰지
  않는다. ②가 통과한 경우 ⑤는 그 판정 결과를 **읽어서 참조만** 한다.
- 스테이지에 넘길 것: 모드(무인/수동), §3이 계산한 `published_count`·`site_age`, 그리고
  **§6(⑥)이 산출한 `n1_count`·`claims_total`·`claims_per_post` 세 값**(Plan 5 판단 라).
  ⑥은 무상태라 원장을 갖지 못하므로(AC #61) ⑤가 대신 스냅샷에 기록한다. **⑤는 세 값을
  해석하지 않고 기록만 하며 D1–D6 표에 넣지 않는다.** §6이 측정에 실패했거나 ⑥이 아직
  구현되지 않았으면 **세 값을 넘기지 않고**, ⑤는 해당 키를 생략한 채 기록한다
  (`hypothesis.py record`의 `key=value` 인자를 주지 않으면 그렇게 된다 — `None`을
  채우지 않는다).
- 스테이지가 돌려줄 것: (가) 최상단 "현재 방향" 블록 (나) ⑤ 리포트 섹션
  (다) 갱신된 `direction-log.json` **내용**(문자열). 파일 쓰기·git은 §10이 한다.
- **무인 모드**: 가설을 `채택`으로 올리지 않고 `제안`까지만 기록한다. 외부 가설 유입
  경로(스테이지 §4)를 실행하지 않는다. (AC #39·#48·#50)
- **수동 모드**: 스테이지 §7의 채택 승인 질문을 거친 것만 `채택`한다.
- ⑤는 `topic-report.md`를 **쓰지도 읽지도 않는다.** (AC #43)

## 8. 리포트 조립
`.claude/audit/audit-YYYY-MM-DD[-HHMM].md`를 아래 골격으로 쓴다(형식은 §9 지침의 조립 규칙을
따른다). 리포트는 `topic-report.md`와 **다른 파일**이며 형식 계약에 묶이지 않는다.

리포트 최상단 순서: (1) 계약 위반 전용 섹션 (2) 원장 정체 경고(링크 원장·방향 원장)
(3) "현재 방향" 블록(채택·확인대기 가설이 있을 때만) (4) 이후 ①②③④⑥⑤ 섹션.
"현재 방향"이 비면 블록 자체를 생략한다 — placeholder를 만들지 않는다. (AC #48)

골격은 섹션 헤딩 순서만 고정한다(각 섹션 내부 서식은 §9·해당 스테이지 지침을 따른다):
1. (있으면) `## ⚠ 계약 위반` — 아래 문단 참조, 항상 최상단
2. (있으면) `## 현재 방향` — 채택·확인대기 가설
3. `## ① 링크 무결성`
4. `## ① 확장: 내부 링크 백필`
5. `## ② 성과 분석`
6. (있으면) `## ③ 색인 건전성` — 단계가 "정상"이면 ③은 H2 없이 한 줄 또는 `### 소견`만
   낸다. 그 경우 이 항목을 만들지 않는다.
7. `## ④ 시스템 스캔`
8. `## ⑥ 수치 무결성`
9. `## ⑤ 방향성 점검`

**계약 위반은 리포트 최상단이다(AC #32).** ④가 (A) 블록을 돌려줬으면 위 골격의 다른 어떤
섹션보다 먼저 배치한다. 4필드 규칙을 적용하지 않으며, 줄 번호·비용을 낼 수 없다는 이유로
드롭하지 않는다. 위반이 0건이면 블록 자체를 생략한다 — "위반 없음" placeholder를 만들지
않는다.

## 9. 리포트 형식 규칙
스테이지가 돌려준 소견은 **위치·증거·제안·비용 4필드**를 모두 갖춘 것만 싣는다. 계약
위반(Python 에러 포함)은 최상단 전용 섹션에 무조건 출력한다. 상세 규칙은 link-check.md
§리포트 조립을 따른다.

## 10. 게시 (git은 여기서만)
- **무인 모드**: `draft`/게시 개념이 없다 — 리포트와 원장은 항상 쓴다.
  1. 리포트 `.claude/audit/audit-YYYY-MM-DD[-HHMM].md`와 원장
     `.claude/audit/link-state.json`·`.claude/audit/direction-log.json`을 명시적으로
     `git add`한다(글롭 금지). 확정 사망 링크 수정 및 백필이 있으면 해당 `content/` 파일도 add한다.
     **②가 게이트를 통과했을 때만** `.claude/audit/topic-report.md`와
     `.claude/audit/topic-history.json`을 쓰고 add한다 — 미충족이면 두 파일에 손대지
     않는다(AC #21). 이 다섯이 AC #36의 산출물 전부이며 여섯 번째 파일을 만들지 않는다.
  2. `git status`로 다른 변경이 섞이지 않았는지 확인한다.
  3. `auto/audit-YYYY-MM-DD[-HHMM]` 브랜치를 만들어
     `git commit -m "audit: YYYY-MM-DD 주간 감사"`로 커밋하고 그 브랜치로 푸시한 뒤
     `gh pr create`로 PR을 만든다. `main`에는 어떤 경우에도 직접 푸시하지 않는다.
  4. 콘텐츠 수정(확정 사망 및 백필)이 0건이면 **콘텐츠 수정 없이 리포트·원장만** 커밋하여 PR을 만든다. (I4 통일)
- **수동 모드**: 링크 수정이 1건 이상이면 (a) 변경 파일 경로 (b) 각 링크의 실패 이력
  (2회 관측 날짜·상태코드)을 상위 10건까지 상세히, 나머지는 "외 N건"으로 제시하고
  "이 링크들을 수정해 main에 푸시할까요?"로 승인을 구한다.
  `topic-report.md`가 갱신되는 경우, 승인 질문에 **주제군별 최종 조정치와 그 근거
  (`r_g`·강등·감쇄)** 를 함께 제시한다. 이 파일은 `rank.md`의 채점에 직접 들어가므로
  링크 수정보다 파급이 크다.
  명확한 긍정만 승인으로 인정한다. 승인 후에만 `git add`(명시 경로) → `git commit` → `git push origin main`.
  승인 전에는 어떤 git 쓰기도 하지 않는다. 링크 수정이 0건이면 리포트·원장을
  `main`에 바로 커밋하되, 이 역시 사용자에게 먼저 알린다.
